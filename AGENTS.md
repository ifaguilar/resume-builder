# Resume Builder

A free, open-source, local-first resume builder. The user edits a resume in a form, sees the real PDF update live, and exports PDFs that ATS parsers and AI screeners read perfectly. The data model is [JSON Resume](https://jsonresume.org/schema).

## Principles

These shape most code decisions:

- **Local-first.** There is no backend, no account and no telemetry. The resume never leaves the device, so don't add network calls, analytics, CDN-hosted assets (fonts, emoji, images) or server functions that receive resume data.
- **ATS-safe by design.** Every PDF must have a clean text layer in reading order. See [PDF and ATS rules](#pdf-and-ats-rules).
- **One source of truth.** A single JSON Resume object holds the data. The form, the preview and every export are derived from it.
- **Data and design stay separate.** `resume` holds JSON Resume data only. `settings` holds presentation only (template, theme, section order). Templates read both and never change the data model.
- **Validation warns, never blocks.** A half-written resume is a valid working state. The Zod schema is strict (unknown keys are reported), but its errors are shown as warnings.
- **The user owns a real file.** The browser keeps an autosaved draft; the user exports or saves a `resume.json` they keep.

## Tech stack

- TanStack Start (React v19, TypeScript v7), with TanStack Router file routes and TanStack Form
- Zod v4 for the JSON Resume schema
- `@react-pdf/renderer` for templates, preview and PDF export, styled with `@react-pdf/tailwind` (`createTw`)
- shadcn/ui on Base UI, Tailwind CSS v4, lucide icons, react-resizable-panels, dnd-kit
- Vitest, oxlint (type-aware), oxfmt, pnpm

TanStack Start renders on the server, but react-pdf must run only in the browser: see the last rule under [Conventions](#conventions).

## Project structure

`src/` follows Screaming Architecture: code is grouped by feature, and code used by several features lives in `src/shared/`.

```
src/
  routes/          TanStack file routes, kept thin (the only place index.tsx is allowed)
  features/
    <feature>/     components, hooks, logic and constants owned by that feature
      constants.ts
      components/
  shared/
    components/ui/ shadcn components (added by `shadcn add`; don't hand-edit)
    lib/           generic helpers
    constants/     constants used by more than one feature
  router.tsx       TanStack Start entry
  routeTree.gen.ts generated by TanStack Router; never edit
  styles.css       Tailwind and shadcn theme
tests/             Vitest suites and fixtures
```

- A feature is named after what it does for the user (`editor`, `resume-form`, `pdf-preview`), not after a technical layer.
- `features/resume/` is the domain model (JSON Resume schema, types, validation, settings schema). It is the one feature other features may import.
- `shared/` never imports from `features/`.
- Constants live in the feature that owns them (`src/features/<feature>/constants.ts`). Constants used by several features go to `src/shared/constants/<topic>.ts`.

## Conventions

- **Filenames are kebab-case**, components included (`form-panel.tsx` exports `FormPanel`). Lint: `unicorn/filename-case`.
- **Imports are always absolute with `#/`**, never `./` or `../`, including dynamic `import()`. Lint: `no-restricted-imports` checks static imports only, so write dynamic imports with `#/` by hand.
- **No barrel files.** Never create `index.ts` or `index.tsx` outside `src/routes/`, and never re-export (`export { x } from`, `export * from`). Import from the file that defines the thing. Lint only catches `export *` (`oxc/no-barrel-file`), so follow this by hand.
- **No magic numbers.** Every number that means something gets a named `const` in a `constants.ts`, with its unit in the name when it has one (`FORM_PANEL_MIN_SIZE_PX`, `PREVIEW_PAGE_PADDING_PT`). Lint: `no-magic-numbers`, but it does not check numbers inside JSX attributes (`minSize={360}`), so use constants there by hand too.
- **No magic strings.** Not lint-checked. Any string the code depends on (ids, keys, storage keys, event names, option values such as `"A4"`, route paths) is a named constant or comes from a typed source (a `const` array, a union type, the schema). Tailwind class strings and user-facing copy are not magic strings; copy stays inline until internationalization.
- **Comments only explain a non-obvious why**: a workaround, a library quirk, a reason that isn't visible in the code. Never restate what the code or a name already says.
- **Tailwind classes stay inline** in `className`. Never wrap them in objects or constants (no `STYLES = { card: "…" }`). When a look repeats, make a component; for conditional classes use `cn()`.
- **The schema mirrors JSON Resume v1.7.0** (`@jsonresume/schema`, `JSON_RESUME_SCHEMA_VERSION`). Every field is optional. Unknown keys and `custom` data are always preserved, never stripped. To upgrade, bump `@jsonresume/schema`, update `resume-schema.ts` until the drift test in `tests/schema.test.ts` passes, then update `JSON_RESUME_SCHEMA_VERSION`.
- **The resume form** uses TanStack Form. Inputs are field components in `features/resume-form/fields/`, registered once in `use-resume-form.ts` and used as `<form.AppField>` / `<group.AppField>` children. Sections use `withForm`, and one entry uses `withFieldGroup`.
  - Icon-only buttons are wrapped in `IconTooltip` (`shared/components/icon-tooltip.tsx`). Its label is both the tooltip and the button's accessible name, so don't set `aria-label` on the button too. Removing a whole entry uses the `destructive` button variant; removing one bullet or keyword uses a ghost × that turns destructive red on hover. Chevrons that only show a field has options are plain icons, not buttons, so they need no tooltip.
  - Warnings come from one form-level validator around `validateResume` and never block anything. A field's warning is hidden while it has focus. Warnings use the amber `warning` theme color (`text-warning`, `border-warning`), never destructive red.
  - An emptied text field stores `undefined`, not `""`. A URL field adds `https://` to a bare domain when it loses focus.
  - Keep the form's spacing scale: `gap-1.5` inside a field (label, control, tip), `gap-6` between fields, and a `border-t pt-6` divider before each named group. Every control gets `border-foreground/15 bg-background shadow-xs` (shadcn's default fill looks disabled on the open section's gray), and every field has an "e.g." placeholder.
  - The form offers only the fields recruiters recommend on a CV. Tips under a field give CV advice only (what makes a strong headline or bullet). They never explain how the form works: if a control needs explaining, fix its label or placeholder instead. Left out on purpose: street address and postal code, profile usernames, work website, summary and per-job keywords, education GPA, courses, location, website, summary and start date, skill levels, and project dates. The list lives in `EDITED_*_KEYS` in `features/resume-form/constants.ts`.
  - The form edits a subset of JSON Resume. Data it can't edit (other sections, unknown keys, `custom`, object locations, dates with a year only or a day) is kept and shown, and is never dropped or rewritten unless the user edits that field.
  - Fields JSON Resume stores as free text but that have common values (fluency, degree) use `AutocompleteField` (Base UI Autocomplete, with a chevron icon so the suggestions are discoverable): users pick a suggestion or type their own. Country uses `CountryField` (shadcn Combobox): it shows names from `Intl.DisplayNames` and stores the ISO code. Both work offline; the country list is `COUNTRY_CODES` in `features/resume/countries.ts`.
  - Every date is picked as month and year (`YYYY-MM`), the one format CVs use. An imported `YYYY` or `YYYY-MM-DD` date is kept and shown until the user picks a month.
- **react-pdf stays client-only.** Import `@react-pdf/renderer` only in files loaded through `React.lazy` inside `<ClientOnly>`. A static import from a server-rendered component breaks SSR and puts react-pdf in the main bundle.

## PDF and ATS rules

Every template must follow these, so the extracted text reads, in order, exactly like the resume:

1. One reading flow, top to bottom in document order; no absolutely positioned text blocks.
2. No letter-spacing tricks on any text (no `tracking-*` classes).
3. Hyphenation and ligatures off: `Font.registerHyphenationCallback((word) => [word])`, and `fontFeatureSettings` with `liga` and `clig` off on the `Page`. Kerning stays on.
4. Bullets are real text characters (`•`), never shapes.
5. Fonts are static Inter WOFF files served locally and registered for every weight and style used; no variable fonts and no woff2 (react-pdf can't use them).
6. Section titles default to the standard words (Summary, Skills, Experience, Education, Projects).
7. Links render their visible text and carry the link annotation.
8. One date format, such as "Sep 2023", with tabular figures.
9. No text inside images, no icons in place of words, no contact details in a page header or footer, no emoji.
10. Empty fields and sections render nothing.
11. Templates are built only from the shared primitives (`Section`, `Entry`, `Bullet`, `Link`) and take sizes, spacing and colors from the design tokens, never one-off values.

## Workflow

- Branch from `dev` as `feat/<name>` (or `fix/`, `chore/`, `docs/`) and open pull requests into `dev`.
- Commit messages follow Conventional Commits (`feat:`, `fix:`, `refactor:`, `chore:`, `docs:`, `test:`, `ci:`).
- CI runs `format:check`, `lint`, `test` and `build` on every pull request to `main` and `dev`, and all four must pass.
- Keep dependencies on `^` ranges; don't pin exact versions.
- Never commit personal data. Fixtures and sample resumes describe fictional people.

## Before finishing

Run `pnpm lint:fix --format=agent` and `pnpm format`, then fix anything oxlint still reports. In Claude Code, a hook already runs both on each edited file, but run them once more over the whole change.
